# 对照 open-claude-ui 手册的主题审查

- 审查日期：2026-11-28
- 审查对象：`dsh-theme-claude` 1.2.1 工作区（这次审查的改动随 1.3.0 发布）
- 对照文档：open-claude-ui 手册，当前基线 Claude Desktop 4.4212.0
- 比对方式：读 `scripts/build.mjs`、`theme.css` 和 `scripts/check.mjs`，对照 v1 与 v4 手册的数值；运行时用 Theme Inspect 确认了 14 个必填令牌
- 同步约定：这份文档随每次改动更新。落地一项就在对应条目上标状态，行号与附一数值跟着改；审查基线之后的新改动记入第七节。

文档会继续更新，具体数值以文末链接的页面为准。这份审查按优先级排：P0 改动小，收益大；P1 要先验证选择器是否命中；最后两部分是取舍和文档问题。每条都给出文档值、当前值和代码位置。

## 结论

令牌层没有问题，14 个必填主题令牌全部覆盖，亮暗成对。composer 双环投影、气泡圆角、陶土色、圆角阶梯、15 阶弹簧都和文档对得上。

差距集中在三处：动效参数、滚动渐隐的触发方式、正文排版比例。P0 四条与 P1 的 5–9 都已处理（第 8 条因宿主标签没有图标，改为压缩而非折叠）；10–12 是保留的偏离。审查基线之后另外修了菜单行焦点环、会话标签行对齐和插件列表整块浮影三处，见第七节；还有几处文档已经和代码矛盾。

## 一、已经一致的部分

- 14 个 `Theme` 必填令牌全部覆盖：`bg-base`、`bg-layer-1/2`、`bg-overlay`、`border-l1/2`、`brand-primary`、`label-primary/secondary`、`state-error/idle/success/warn`、`sidebar-fill`。
- composer 的常态、悬停、聚焦三组投影，与 v1 §1.4.4 的公式逐值一致（`theme.css:478` 起）。
- 用户气泡 18px 圆角、`12px 16px` 内边距，与 v1 §1.3 一致。
- 陶土 `#c6613f`、悬停 `#d97757`，与 v4 §4.3.3 的实测值一致。
- 圆角 `xs/sm/lg` 已是 v4 的 5/7/10。
- 15 阶 `linear()` 弹簧、`@starting-style` 入场、28px 渐隐、宽表钉列，文档里都有对应。

## 二、P0 建议修改

### 1. 字号升到 17px，行高还停在 21px（已修复）

文档：正文 14/20，比例 1.43；prose 14 到 16px、行高 20 到 24px，比例 1.43 到 1.5。

现状：`--dsh-content-font-size` 是 `calc(17px + delta)`，`--dsw-font-markdown-base` 的行高是 `calc(21px + delta)`，比例 1.235。字号调到 19px 时，行高 23px，比例 1.21。

后果：中文长段读起来挤，字号越大越挤。

**状态：已修复（2026-11-28）。** 行高改为 `calc(var(--dsh-content-font-size) * 1.5)`，定义在 `html` 上；`--dsw-font-markdown-base`、`base-strong`、`base-italic` 及对应的行高令牌全部引用它。17px 时行高 25.5px，比例 1.5，字号调大等比跟随。`check.mjs` 增加了守卫：比例不得低于 1.45，三个 base 令牌不得写死 px。

位置：`theme.css:251`、`theme.css:286`；守卫 `scripts/check.mjs:111`；`scripts/build.mjs:591` 同步生成该令牌。

### 2. 骨架屏的时长、缓动和错峰（已修复）

文档：动效是 `cds-skeleton-breathe`，2s，`ease-in-out`，关键帧透明度 1 → 0.6 → 1。wave 模式每块延时 `reveal-end + i × 90ms`。扫光是独立元素，2s，`linear`，渐变 105°（RTL 是 255°，并反转方向）。

现状：`claude-sheen`，1.6s，`cubic-bezier(0.65, 0, 0.35, 1)`，透明度 0.75 到 1。所有块同时呼吸，没有错峰。

**状态：已修复（2026-11-28）。** 呼吸换成 `claude-skeleton-breathe`，2s `ease-in-out`，0%/100% 为 1、50% 为 0.6；同组第 n 块加 `(n-1) × 90ms` 延时。扫光拆成独立的 `::after`，2s `linear`，105° 渐变，RTL 用 255° 并 `animation-direction: reverse`。动画只作用于叶子块，避开宿主嵌套的 `skeletonRow` / `skeletonBars` / `skeletonCard` 容器，否则两层透明度叠加。

位置：`theme.css:1445`、`theme.css:1454`；守卫 `scripts/check.mjs:136`。

### 3. 滚动渐隐一直挂着（已修复）

文档：用 `@property` 注册 `--cds-scroll-fade-top/bottom`，由 `animation-timeline: scroll()` 驱动。触顶或触底时，渐隐归零。

现状：五段式 `mask-image` 直接挂在滚动容器上，不判断滚动位置。

后果：内容只有三四行时，第一行和最后一行也被削掉一截。

**状态：已修复（2026-11-28）。** `@property` 注册 `--claude-scroll-fade-top/bottom`（`<length>`，初值 0）；两个关键帧分别在这两个变量上做 0→28px 和 28px→0，动画挂容器自己的 `scroll(self)` 时间轴，`animation-range` 为 `0 28px` 与 `calc(100% - 28px) 100%`，`both` 填充让中段保持 28px。没有可滚动高度时时间轴不激活，两个变量停在 0，mask 自动变成无操作；内容短到只有几行时不再削首尾。五段的衰减曲线保留，只是两端长度改由变量控制。

位置：`theme.css:1550`、`theme.css:1567`；守卫 `scripts/check.mjs:175`。

### 4. 分段控件内缩 2px（已修复）

文档：轨道 `padding: 1px`，指示器 `top: 1px; bottom: 1px`。选中态是 `inset 0 0 0 0.5px` 发丝环，加 `0 1px 2px` 和 `0 2px 6px -1px` 两层投影。

现状：`padding: 2px`、`gap: 2px`；选中态只有一层 `0 1px 2px`。

**状态：已修复（2026-11-28）。** 轨道内缩改 1px，胶囊高度从 28px 变为 26px；选中态补 `inset 0 0 0 var(--claude-ring)` 发丝内环（1x 1px、2x 0.5px、3x 1/3px）和 `0 1px 2px`、`0 2px 6px -1px` 两层投影，暗色用 8% 白内环与 30% / 25% 黑投影，与 v1 §2.2.1 对齐。

位置：`theme.css:1308`、`theme.css:1346`；守卫 `scripts/check.mjs:208`。

## 三、P1 项的处理

### 5. Retina 发丝边（已修复）

文档：`min-resolution: 2dppx` 时环宽 0.5px，3dppx 时 1/3px，画法用 `box-shadow: inset 0 0 0 0.5px`。

现状：分段选中态已用 0.5px 内环（第 4 条）；卡片、表格、代码块仍是固定 1px。

原因：DSH 的边框只暴露颜色令牌，宽度写在宿主规则里。只能在卡片、表格、代码块这类关键盒子上自己补。

**状态：已修复（2026-11-28）。** 新增 `--claude-ring`：1x 为 1px、2dppx 为 0.5px、3dppx 为 1/3px。composer 与分段选中态的内环直接读它；代码块、文件卡、交付卡和宽表改用 `::after` 覆盖环——Chromium 会把亚像素 `border` 进位成 1px，普通 inset 阴影又会被通栏的代码标题条盖住。3x 下实测环宽 0.333px。

位置：`theme.css:762`、`theme.css:782`；守卫 `scripts/check.mjs:229`。

### 6. 暗色字重和描边（已修复）

现状：`body` 同时设了 `font-weight: 500` 和 `-webkit-text-stroke: 0.12px`。这两个属性都会继承，12px 的代码文字也被加粗描边。

文档：暗色模式把字重下调 30 到 40，抵消白字在黑底上的光渗。

**状态：已修复（2026-11-28）。** 暗色 `body` 降到 400（宋体没有可变字重轴，取最接近的整数档）；`pre`、`code`、`kbd`、`samp` 的描边置 0，不再继承 body 的 0.12px。

位置：`theme.css:1212`、`theme.css:1216`；守卫 `scripts/check.mjs:251`。

### 7. 按压弹簧只给了 chip（已修复）

文档：`.cds-btn-squish` 缩放 0.975，配 15 阶弹簧，适用于所有按钮。

现状：chip 按 0.94 且带弹簧；composer 按钮按 0.96，无弹簧；面板行按 0.985，无弹簧。

**状态：已修复（2026-11-28）。** 抽了 `--claude-press: 0.975`，按钮、面板行、`_newSession`、chip/pill 共用一条 `:active` 规则：按下 60ms `ease-out`，松开走 450ms 的 15 阶弹簧。原来的 0.94 / 0.96 / 0.985 三套已删。

位置：`theme.css:1397`、`theme.css:1759`；守卫 `scripts/check.mjs:264`。

### 8. 分段控件没有容器查询（已处理，改法不同）

文档：容器宽度 ≤180px 时折叠两项控件的标签；三项的阈值是 ≤254px。

现状：主题里 `@container` 出现 0 次。宿主 bundle 里有 137 处，说明结构支持。

难点：实测标签包在 `_tabLabel` 的 span 里，但 DSH 的视图标签只有文字、没有图标。按文档隐藏非选中项的文字，会留下空胶囊，不能照搬。

**状态：已处理（2026-11-28，改法不同）。** 标签行外层 `div:has(> [data-conversation-tabs])` 成为 inline-size 容器：≤254px 收紧 gap 与内距，≤180px 再降字号；文字始终保留，是有意偏离。

位置：`theme.css:1320`、`theme.css:1369`、`theme.css:1379`；守卫 `scripts/check.mjs:282`。

### 9. 两个暗色值掉出色阶（已修复）

- `--dsw-alias-label-caption` 暗色是 `#8a8a8a`。文档说 muted 亮暗同值，应为 `#898781`。
- `--dsw-alias-markdown-code-block` 暗色是 `#0b0b0a`。35 阶灰阶里是 `#0b0b0b`。

**状态：已修复（2026-11-28）。** 两个值都已回阶，代码块的未选中分段也一并改成 `#0b0b0b`。

位置：`theme.css:370`、`theme.css:387`。

## 四、可以保留的偏离

### 10. 全局衬线

文档的字阶矩阵里，按钮 12.5px、分段 12px、正文 14px 都是无衬线，衬线只给 38px 的问候语和长文正文。主题把按钮、菜单、状态栏、侧栏都换成了宋体。

这是主题辨识度最高的地方，不算 bug。折中方案是正文和标题保留衬线，控件回无衬线。

位置：`theme.css:1199`、`theme.css:549`。

### 11. 陶土 accent

v4 把 accent 角色定成蓝色（亮 `#184f95`，暗 `#86b6ef`），陶土只留给 brand。1.1.9 之前，主题的链接正是 `#184f95`，后来主动改成陶土。

要严格符合文档，链接、焦点环、选区都该回蓝。建议保留陶土，在 CHANGELOG 里写清这是有意偏离。

### 12. 亮色画布

文档的桌面端画布是 `#fcfcfb` 和 `#f9f9f7`。主题用 claude.ai 网页的 `#faf9f5`，不在 35 阶灰阶内。三者的数值很接近，保留更统一。

## 六、不建议追

- 弹窗六档宽度、嵌套虚化：要宿主动态属性，收益低于成本。
- 附件 7.5rem 磁贴、双向中间截断：宿主附件结构不同，改不了。
- `data-mode` 三态作用域：宿主只有明暗两态，硬造会出 bug。
- 全量移植 55 个关键帧、24 个 `@property`：v4 只实测到 4 个缓动值，v1 的“7 条官方曲线”并未全部证实。

## 七、审查之后的改动

审查基线之后落地的改动记在这里；上面列的待办里，P0 四条都已完成。

1. **菜单/列表行不再画焦点环**（2026-11-28）。浅色模式下鼠标划过模型菜单的某一行，整行会套一圈陶土描边，看起来像报错。原因是 DSH 在指针移动时把真实焦点移到该行（模型菜单的 `onMouseMove` 调 `focus()`），Chromium 又把它算作 `:focus-visible`，全局焦点环于是跟着鼠标走。现在菜单、列表行不画主题焦点环，焦点交给宿主的悬停底色。位置：`theme.css:1094`；守卫 `scripts/check.mjs:359`。
2. **会话标签行对齐**（2026-11-28）。宿主按 25px 行高居中标签行，并把「更多视图」按钮上提 3px，而主题的胶囊当时高 28px（P0-4 之后是 26px）。现在标签行按胶囊居中，底部补 10px，与上方 10px 对称，「更多视图」按钮不再偏移。位置：`theme.css:1317`、`theme.css:1323`。
3. **暗色下插件列表整块浮影**（2026-11-28）。插件页是 `_cards` > `_card` > `_cardContent`，`[class*='_card']` 的子串匹配会选中 `_cards` 容器；`:hover` 在指针进入子元素时也命中祖先，于是暗色那条 `_card` 悬停投影让整块 grid 浮起。删掉暗色投影，卡片亮暗一致不上浮。位置：`theme.css:1587`；守卫 `scripts/check.mjs:758`。
4. **弹出菜单的滚动条闪一下又消失**（2026-11-28）。菜单项入场原本从 `translateY(4px)` 开始，位移把列表的 `scrollHeight` 临时撑大 4px，能完整显示的菜单也冒出滚动条；动画结束、位移归零后滚动条消失，选项随即向右补宽。中途试过改成淡入，顶部两排仍会先闪；最终把菜单入场整个去掉（连同宿主 40ms 的直接子元素淡入），打开即显示文字，退场动画保留。面板行和英雄行的上浮不变。位置：`theme.css:1498`；守卫 `scripts/check.mjs:295`。
5. **模型选择与权限选择不一致**（2026-11-28）。模型菜单顶部两格是 `menuitem`、模型列表是 `menuitemradio`，之前只有部分行有入场动画，看起来一半一半。现在菜单没有入场动画，两处同时直接出现；模型触发器字重也从 400 提到 500，和权限触发器一致。位置：`theme.css:1498`、`theme.css:1173`；守卫 `scripts/check.mjs:295`、`scripts/check.mjs:315`。
6. **导入按钮与新会话不同色**（2026-11-28）。`dsh-deepseek-chat-import` 的宽列导入按钮固定用 `--dsw-alias-button-elevated-fill`，而新会话在 macOS 上走 `--dsw-specific-sidebar-glass-fill`，并排时一白一米。宽列导入按钮改读同一组 glass-fill；新会话的悬停底色被主题清掉，导入按钮也跟随透明；收起态没有 `.wide`，保持透明。位置：`theme.css:559`；守卫 `scripts/check.mjs:346`。
7. **弹出菜单在暗色下仍是冷蓝灰**（2026-11-28）。宿主菜单材质用 `--dsw-menu-surface-fill`，暗色默认 `rgba(48,49,54,.64)`，主题一直没覆盖，所以「+」打开的菜单还是原生蓝。现在从主题自己的 `--dsw-specific-menu` 派生 92% 填充，暖色、半透明与背景模糊都保留。宿主把默认值写在 `body` 上，普通覆盖会输给后挂的样式表，所以规则用 `html body` 加 `!important`。位置：`theme.css:1804`；守卫 `scripts/check.mjs:777`。
8. **文档预览选区仍是原生蓝**（2026-11-28）。正文 `::selection` 早已改成陶土，但 `--dsw-alias-bg-document-selection` 还沿用宿主的 `#2a78d6` / `#6da7ec`。现在统一为陶土 22% / 30%。位置：`theme.css:96`、`theme.css:306`；守卫 `scripts/check.mjs:787`。
